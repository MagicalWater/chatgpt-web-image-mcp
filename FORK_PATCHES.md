- Required fail-fast behavior: when ChatGPT produces an unambiguous assistant reply showing that image generation did not begin (for example, a request to upload required source images), result polling must stop and return a terminal machine-readable error instead of waiting for `IMAGE_GENERATION_TIMEOUT`. - Cross-process reliability contract: a failed generation must not leave a live profile lease that blocks a subsequent independent MCP process or AI caller from using the same dedicated profile.

### Fixed multi-profile worker pool / concurrent generation

- Status: Windows and macOS implementation / production acceptance PASS on 2026-08-16.
- Scope: add an optional fixed 1–3 worker scheduler above the existing `ImageGenerator`. Each worker owns its own dedicated Chrome profile, profile lease, generator/session instance, and account-switch command. Existing single-worker configuration remains supported unchanged.
- Scheduling contract: generation jobs receive only a temporary worker assignment. There is no permanent conversation-to-profile binding and no unbounded FIFO queue. Different workers may run concurrently; operations remain serialized inside each worker.
- Cross-process contract: profile leases remain the correctness authority. Pool mode uses a short per-candidate profile acquisition window while scanning workers, then returns `BROWSER_POOL_BUSY` after a bounded total pool wait if no worker becomes available. Every pooled job closes its worker browser session in `finally`, including successful jobs, so the profile lease returns to the shared pool for other MCP processes.
- Isolation contract: pool configuration rejects duplicate worker IDs, duplicate Chrome profile paths, duplicate account-switch commands, CDP mode, and worker counts outside 1–3. Account-ring membership itself is not introspected because doing so would require reading browser/account-switcher secret state; production acceptance must prove worker A switching does not alter worker B and vice versa.
- Project/context boundary: fixed ChatGPT project or conversation URLs may be account-scoped. Pool generation therefore fails closed with `POOL_AFFINITY_REQUIRED` for non-portable account-scoped URLs instead of guessing a worker. Portable root chat and Images jobs remain schedulable. No permanent conversation-to-profile binding is introduced.
- Executor/bridge scope review: `gpt-computer-bridge` `call_executor_tool` creates an independent Executor MCP client per invocation and exposes no global serialization queue, so worker scheduling remains correctly owned by this fork. Fresh Executor source review on 2026-08-16 additionally confirmed that downstream stdio MCP connections are strictly per-call: `invoke.ts` pools remote MCP sessions only, while stdio creates a fresh `StdioClientTransport` and closes it at invocation end. Therefore a scheduler cursor stored only in the Image MCP process would reset to worker A on every sequential production call. This fork now persists only the next worker index and configured worker IDs in machine-local `~/.chatgpt-web-image-mcp/worker-pool-cursor.json`, protected by a short atomic cross-process lock. Sequential calls start A -> B -> C -> A when all three are idle; concurrent calls atomically reserve distinct starting workers before normal profile-lease fallback. An ownerless cursor lock is reclaimed only after a bounded stale-age grace, closing the mkdir-before-owner-write crash window without weakening live-owner safety. Later macOS long-running acceptance did expose a separate transport timeout: the DevSpace adapter allowed a 600-second MCP tool deadline while Node/undici could abort a silent HTTP response at its approximately 300-second default headers timeout. That issue is fixed in the bridge's existing DevSpace carried-patch layer, not in Executor or this pool scheduler. Accepted DevSpace authority is upstream baseline `v1.0.7`, carried-patch commit `3536d1c63ec1f879711fb48afca882c756e0428a`, release tag `gcb-v1.0.7-p3`.
